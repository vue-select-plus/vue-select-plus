# Changelog

All notable changes to Vue Select Plus are documented here. Going forward, this file is generated by [Changesets](./.changeset/README.md).

The project follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html). The three published packages — `@vue-select-plus/core`, `@vue-select-plus/vue`, `@vue-select-plus/styles` — are released together on the same version.

---

## Unreleased — towards `1.0.0`

This release reworks the component from the inside out. Most consumers will only see additive props and improved a11y; a handful of changes require small migrations (see below).

### Added

- **WAI-ARIA 1.2 combobox pattern** end-to-end. `role="combobox"` now sits on the focusable element (`<button>` or `<input>`), with `aria-haspopup="listbox"`, `aria-autocomplete="list"` (searchable), `aria-controls`, `aria-activedescendant`, `aria-expanded` and `aria-busy`.
- Selected value is now announced as part of the combobox's accessible name via an `aria-labelledby`/`aria-describedby` chain.
- Options expose `aria-setsize`, `aria-posinset`, `aria-level`, and `aria-expanded` for tree nodes.
- Listbox carries `aria-multiselectable` in multi mode and a polite live region announces result counts, loading state, and below-min-search hints.
- Tag-remove and clear buttons are reachable via Tab with proper `aria-label`s.
- Focus returns to the trigger on `Escape` and on selection in single mode.

- **Floating UI** (`@floating-ui/vue`) positions the dropdown. Auto-flips when out of space, sticks to the trigger width, shifts to stay inside the viewport.
- New `teleport` prop — defaults to `<body>` so the dropdown escapes `overflow: hidden`, `transform`, and z-index ancestors. Pass `false` to render inline, or a CSS selector / `HTMLElement` to retarget.
- New `placement` prop (re-exports `Placement` type from `@floating-ui/vue`).
- New `maxMenuHeight` prop with viewport-aware clamping.

- **Async / server-side search**:
    - `loading` prop drives an inline spinner, sets `aria-busy="true"`, and announces "Loading…" to AT.
    - `filterable` prop (default `true`); set to `false` to delegate filtering to the parent (`@search` event).
    - `minSearchLength` gates the `@search` event and shows a "Type at least N characters" hint.
    - `searchDebounce` (ms) debounces the outbound `@search` event without blocking input responsiveness.

- **Native form integration**: `name` prop emits hidden `<input>`s (one per value in multi mode) so the component serializes via `FormData` like a native `<select>`.
- **HTML5 `required` validation**: combined with `validateOnSubmit` (default `true`), form submission is blocked while the model is empty and the browser surfaces its native tooltip. `validationMessage` customises the message.
- New `clearable` prop with a keyboard-reachable clear button (Tab-targetable; survives loading state).
- New `size` prop: `'sm' | 'md' | 'lg'`.
- New `autocomplete` and `inputmode` props are forwarded to the searchable input.

- **Theming**:
    - `.vsp-dark` class added as a Tailwind-safe alternative to `.dark`. Both work; `.vsp-dark` is recommended when Tailwind's dark mode is already in play.
    - `prefers-reduced-motion` now disables transitions and the spinner animation.
    - `forced-colors` (Windows High Contrast) is fully styled with system colours.
    - More CSS variables for fine-grained theming.

- **`labels` prop** for full i18n of every screen-reader string (`clear`, `removeItem(label)`, `noResults`, `addChild`, `resultsCount(n)`, `loading`, `typeToSearch(min)`).

- **Open/close transitions** with placement-aware origins. Disabled under `prefers-reduced-motion`.

- **Component template ref API** via `defineExpose`: `open()`, `close()`, `focus()`, `clear()`.

- New events: `@open`, `@close`, `@search`.

- **Tests**:
    - Core composable tests expanded (21 → from 5).
    - 27 component-level tests added (ARIA wiring, behaviour, SSR smoke).
    - Storybook a11y addon configured to run axe against every story.

- **GitHub Actions CI**: install / type-check / test / build matrix on Node 20 + 22, with a per-PR bundle-size report.

### Changed

- **`useId()` (Vue 3.5)** replaces `Math.random()` for ID generation — IDs are now SSR-safe and hydrate without mismatch.
- **Public API of `@vue-select-plus/core` is now `useSelect`, `useClickOutside`, and the public types only.** Internal composables (`useSelectState`, `useKeyboard`, `useOptions`, `useSelection`, `useCreator`) are no longer re-exported. If you depended on them, switch to `useSelect` or pin to `0.0.2`.
- **`useClickOutside`** now listens to `pointerdown` in the capture phase (was `mousedown`/`touchstart` in bubble phase). It now also accepts an array of targets — pass both your trigger and the menu element when the menu is teleported.
- **`labelMap` computed** replaces the old O(n²) label lookup in trigger rendering. Public API of `useSelect` now exposes it.
- **`SelectModelValue`** narrowed: `string | number | (string | number)[] | undefined | null` (was `any`). The arbitrary `[key: string]: any` index signature on `SelectOption` is gone.
- **CSS variables** renamed/added for consistency:
    - `--vs-primary-focus` → `--vs-focus-ring` (now a full `box-shadow` value, with stronger contrast).
    - New: `--vs-bg-elevated`, `--vs-bg-subtle`, `--vs-bg-hover`, `--vs-bg-active`, `--vs-text-disabled`, `--vs-tag-bg`, `--vs-tag-text`, `--vs-shadow-menu`, `--vs-z-menu`, `--vs-control-height`, `--vs-font-size`.

### Fixed

- Searchable mode no longer toggles the menu closed-open-closed on every click (event-bubble between input and control wrapper).
- Search query is debounced separately from input responsiveness — input updates immediately, `@search` is rate-limited.
- The dark theme no longer leaves group headers, action buttons, or hover backgrounds in light-mode colours.
- Logical CSS properties throughout (`margin-inline-start`, `padding-block`, …) — RTL out of the box.
- Listbox now carries `aria-multiselectable` in multi mode, fixing the AT announcement of multi-select capability.
- Clear button no longer disappears during `loading` — both indicators can coexist with a subtle divider.
- Duplicate `<!-- Dropdown (Virtual) -->` comments removed.

### Breaking changes

- **Peer dependency:** `vue` is now `^3.5.0` (was `^3.0.0`). `useId()` requires 3.5+.
- **`@vue-select-plus/core` public API shrunk** — see "Changed" above.
- **Menu DOM location:** with `teleport: true` (the new default), the listbox is mounted at `<body>`, not as a child of the trigger. Tests, integration code, or styling that relied on parent-relative selectors should either pass `teleport: false` or use the documented data attribute (`data-placement`) and root classes.
- **Combobox markup:** `role="combobox"` is now on a `<button>` or `<input>` (not the wrapper `<div>`). Tests that queried `[role="combobox"]` still work; tests that queried the wrapper need adjustment.
- **Auto-generated IDs** changed prefix from `v-select-{random}` to `vsp-{useId}`.

### Migration notes

| If you used … | Do this |
| :--- | :--- |
| `useKeyboard`, `useSelectState`, `useOptions`, `useSelection`, `useCreator` directly | Switch to `useSelect`. The internals stay in the package but are no longer in `exports`. |
| `aria-labelledby` against the wrapper div in tests | Query `[role="combobox"]` instead — that's the focusable element now. |
| CSS selectors like `.vue-select-root [role="combobox"]` | Same, but note the combobox is a button/input, not a div. |
| Custom dark theme on `.dark` | Still works; consider switching to `.vsp-dark` if you also use Tailwind. |
| Form validation libraries | Set `:validate-on-submit="false"` and continue handling validation yourself. |
