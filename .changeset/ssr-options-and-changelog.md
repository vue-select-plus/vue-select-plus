The "missing `options` prop throws TypeError" guard I added in 0.1.5
was setup-time and SSR-hostile. Apps that hand the component a model
whose initial value is `undefined` or `null` — a normal pattern with
`useFetch`-on-mount, suspense, or any async data flow — would 500 on
the server render.

The guard is gone. `useSelect` is now wired with
`() => props.options ?? []`, so a missing prop renders as an empty
combobox instead of taking the page down. TypeScript still flags the
omission at compile time, and Vue's dev-mode prop validation still
warns at runtime — that signal was always there.

Also: CHANGELOG.md was being generated by Changesets but never made
it into the published tarball. Added to the `files` array in all
three packages.
